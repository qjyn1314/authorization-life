# Claude Code 使用最佳实践

本文件沉淀在本项目使用 Claude Code 的推荐方式与经验，作为团队约定。配套阅读 `.claude/memory/memory-convention.md`（记忆存放约定）。

## 核心原则

**让知识的「加载时机」匹配它的「使用频率」**：每次都要用的放自动加载层，偶尔查的放按需层，个人的放本地层，跨项目的放全局层。

## 四层记忆模型（always-on -> on-demand）

| 层 | 文件 | 加载时机 | 放什么 |
|----|------|----------|--------|
| ① 项目主记忆 | `CLAUDE.md`（项目根） | 每次会话**自动加载** | 精炼全貌：技术栈、模块、端口、启动命令、关键约定 + 指向深文件的指针 |
| ② 分类深记忆 | `.claude/memory/<分类>/*.md` | **按需读取** | 某主题深度细节（OAuth 流程、DB schema、编码规范等） |
| ③ 个人/本地 | `CLAUDE.local.md`（gitignore） | 自动加载，**不进 git** | 个人偏好、密钥、本地路径、临时笔记 |
| ④ 全局个人 | `~/.claude/CLAUDE.md` | 所有项目自动加载 | 跨项目的个人工作习惯（如"回答用中文""commit 风格"） |

## 黄金规则

1. **`CLAUDE.md` 要"瘦"**：它每次会话都进上下文、消耗 token。放「80% 场景用到的 80% 信息」，其余用「详见 `.claude/memory/...`」指针引向深文件。忌把所有内容塞进去。

2. **指针 > 内联**：`CLAUDE.md` 是地图，不是百科全书。让 Claude 知道「去哪查」，而不是平铺全部内容。

3. **项目知识进仓库**：项目事实放 `.claude/memory/` 并提交 git（团队共享、随代码版本化）；**不要**放全局 `~/.claude`。全局只放真正的个人跨项目习惯。

4. **一文件一主题、分类存放**：便于精准定位与更新。事实变了就改对应那个文件--**错误的记忆比没有记忆更糟**，陈旧记忆会误导决策。

5. **不重复代码/git 已记录的**：记忆只存「非显而易见」的约定、决策、运维事实；可从代码或 git 历史直接读出的不记。

6. **关键事实必须在 `CLAUDE.md`**：深记忆是按需读取的，Claude 不一定每次都读；所以「必须知道」的（端口、启动方式、危险操作、约定）要进 `CLAUDE.md`，不能只放在深文件里等被翻到。

7. **变更即更新**：改了端口/版本/模块/约定，当场更新对应记忆文件与索引，像维护代码一样维护记忆。

## 进阶：`@` 导入语法

`CLAUDE.md` 支持 `@path/to/file` 导入其他文件内容（如 `@.claude/memory/architecture/tech-stack.md`），被引文件会在加载时一并读入。

- 适用：「几乎每次会话都要看」的深文件。
- 慎用：会抵消「瘦」的好处，增加每次会话的 token 成本；非必要不导入。

## 提问与协作建议

- **给上下文**：让 Claude 改代码前，先指明相关模块/文件（或让它先读 `CLAUDE.md` + 对应 memory），减少盲改。
- **先读后改**：涉及陌生模块时，要求 Claude 先读代码与对应记忆文件再动手。
- **小步验证**：复杂改动分步进行，每步跑通再继续；要求 Claude 如实报告测试结果，不轻信"已完成"。
- **难逆操作先确认**：删除、覆盖、外发、提交等操作，要求 Claude 先说明再做（除非已明确授权）。
- **用 `!` 跑命令**：交互式登录等需你亲自执行的命令，在输入框用 `! <command>` 直接在本会话运行，输出进对话。

## 本项目当前配置（自检对照）

本项目已按上述推荐落地：

- ✅ 项目内 `.claude/memory/` 分类存储（architecture / domain / engineering）
- ✅ 瘦 `CLAUDE.md` 作主入口，含「记忆约定」必读段与指针
- ✅ 不写入用户全局记忆目录（`C:\Users\<user>\.claude\projects\...`）
- ✅ `MEMORY.md` 索引 + `memory-convention.md` 约定齐备

- ⬜ 可选：跨项目个人习惯放入 `~/.claude/CLAUDE.md`

> 维护纪律：事实变了就更新对应文件；新增记忆归入合适分类并在 `MEMORY.md` 登记。
